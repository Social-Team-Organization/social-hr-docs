# الأدوار والصلاحيات

من يقوم بماذا في Social HR — عبر [لوحة التحكم](./PLATFORM.md) (Control plane) ومساحات عمل الموارد البشرية للعملاء.

يعتمد Social HR على التحكم في الوصول حسب الدور (Role-based access) داخل كل مساحة عمل. تُمنح الصلاحيات عبر سجلات الموظفين ومجموعات المستخدمين وإعدادات الصلاحيات الفردية. لا توجد باقات منتج منفصلة للأدوار.

> | الدور | السطح | النطاق |
> |------|-------|--------|

> | [مسؤول الموارد البشرية](#hr-administrator) | مساحة عمل العميل | عمليات شؤون الموظفين |
> | [المدير](#manager) | مساحة عمل العميل | الموافقات + رؤية الفريق |

سيناريوهات حسب الشخصية: [حالات الاستخدام](./USE_CASES.md).

## Platform operator — مشغّل المنصة {#platform-operator}

**أين:** لوحة [لوحة التحكم](./PLATFORM.md) على النطاق الرئيسي لـ Social HR.

**من:** موظفو Social HR الحاصلون على بيانات اعتماد الوصول إلى المنصة.

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **دورة حياة [المستأجر](./PLATFORM.md) (Tenant)** | إنشاء مساحات عمل العملاء وعرضها وتعديلها وإيقافها وإعادة تفعيلها وحذفها |
| **إدارة [الباقة](./PLANS.md) (Plan)** | تعيين باقات الاشتراك وتغييرها |
| **[تجاوزات الوحدات](./PLATFORM.md) (Module overrides)** | فرض تفعيل أو إيقاف وحدات محددة لعملاء بعينهم |
| **حالة الحساب** | تعيين: تجريبي (Trial)، نشط (Active)، متأخر السداد (Past due)، موقوف (Suspended)، ملغى (Cancelled) |
| **وصول الدعم** | فتح مساحات عمل العملاء للتحقق واستكشاف الأخطاء |
| **إدارة الفهرس** | عرض الباقات وفهرس الوحدات |

### ما لا يستطيع مشغّلو المنصة فعله

- تسجيل الدخول إلى مساحات عمل العملاء ببيانات اعتماد المنصة (يلزم تسجيل دخول منفصل)
- عرض بيانات الموارد البشرية للعملاء (الموظفون، قسائم الراتب، الحضور) من لوحة التحكم
- تعديل إعدادات مؤسسة العميل مباشرة

### الصلاحيات المعتادة

يُمنح وصول موظفي المنصة عبر بيانات اعتماد الموظفين على النطاق الرئيسي — منفصلة عن أي حساب مستخدم في مساحة عمل العميل.

السيناريوهات: [حالات الاستخدام — مشغّل المنصة](./USE_CASES.md#platform-operator-scenarios). التفاصيل: [المنصة — لوحة التحكم](./PLATFORM.md#control-plane).

## Tenant admin — مدير المؤسسة {#tenant-admin}

**أين:** مساحة عمل الموارد البشرية للعميل.

**من:** مسؤول تقنية الموارد البشرية الرئيسي في المؤسسة — غالباً أول مستخدم يُنشأ أثناء [التجهيز](./PLATFORM.md) (Provision).

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **إعداد المؤسسة** | الأقسام، المسميات الوظيفية، [أنواع العمل](./FEATURES.md#geofencing-and-work-type-location-policies) (Work types)، الورديات، العطل الرسمية |
| **ضبط السياسات** | [السياج الجغرافي](./MODULES.md#geofencing) (Geofencing)، [تسجيل الحضور بالتعرف على الوجه](./MODULES.md#face-check-in) (Face Check-In)، [تتبع النشاط](./MODULES.md#activity-tracking) (Activity Tracking)، قواعد الحضور |
| **إدارة المستخدمين** | إنشاء المستخدمين، تعيين مجموعات الصلاحيات، إدارة صلاحيات الموظفين |
| **إعداد البريد** | إعدادات خادم البريد الإلكتروني للمؤسسة |
| **إعدادات الوحدات** | ضبط جميع [الوحدات](./MODULES.md) المستحقة (ضريبة الرواتب، أنواع الإجازات، مراحل التوظيف، إلخ) |
| **التكاملات** | LDAP، أجهزة البصمة، إعدادات النسخ الاحتياطي (عند الاستحقاق) |
| **البيانات الأولية** | استيراد الموظفين، إعداد الهيكل التنظيمي، ضبط سلاسل الموافقة |

### الصلاحيات المعتادة

وصول كامل إلى الإعدادات (Settings) وإعدادات النظام (Configuration) وجميع الوحدات المستحقة. يمكنه منح الصلاحيات أو سحبها من المستخدمين الآخرين.

السيناريوهات: [حالات الاستخدام — مدير الموارد البشرية للمؤسسة](./USE_CASES.md#tenant-hr-admin-scenarios).

## HR administrator — مسؤول الموارد البشرية

**أين:** مساحة عمل الموارد البشرية للعميل.

**من:** أعضاء فريق الموارد البشرية المسؤولون عن عمليات شؤون الموظفين — قد يكون لديهم أو لا صلاحيات [مدير المؤسسة](#tenant-admin).

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **سجلات الموظفين** | إنشاء الموظفين وتحديثهم وإلغاء تفعيلهم؛ إدارة معلومات العمل |
| **إدارة الإجازات** | ضبط أنواع الإجازات، تخصيص الأرصدة، إدارة إجازات الشركة |
| **إشراف الحضور** | مراجعة سجلات الحضور، ضبط فترات السماح وتقييد عنوان IP |
| **Recruitment — التوظيف** | إدارة حملات التوظيف والمرشحين ومسار التوظيف (عند الاستحقاق) |
| **Onboarding — التهيئة** | إدارة لوحات مهام الموظفين الجدد (عند الاستحقاق) |
| **Offboarding — إنهاء الخدمة** | إدارة عمليات إنهاء الخدمة (عند الاستحقاق) |
| **Documents — المستندات** | طلب مستندات الموظفين وتتبعها |
| **الإعلانات** | نشر إعلانات على مستوى المؤسسة |
| **وثائق السياسات** | توزيع سياسات الموظفين وتتبع الإقرار بها |
| **التقارير** | الوصول إلى تحليلات لوحة المعلومات وتقارير الوحدات |

### الصلاحيات المعتادة

وصول واسع إلى وحدات الموارد البشرية. قد يكون أو لا يكون لديه وصول إلى الإعدادات حسب سياسة المؤسسة. عادةً لا يستطيع إدارة صلاحيات المستخدمين ما لم يُمنح ذلك صراحة.

مرجع الوحدات: [الوحدات](./MODULES.md).

## Manager — المدير

**أين:** مساحة عمل الموارد البشرية للعميل.

**من:** الموظفون الذين لديهم مرؤوسون مباشرون — يُحدَّدون عبر علاقة **المدير المباشر** (Reporting manager) في سجل معلومات عمل الموظف.

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **الموافقات** | طلبات الإجازة، طلبات الحضور، [طلبات نوع العمل](./FEATURES.md#geofencing-and-work-type-location-policies)، طلبات الوردية، طلبات الأصول، العمل الإضافي |
| **[التحقق من الحضور](./MODULES.md#attendance) (Attendance validation)** | مراجعة سجلات حضور الفريق والتحقق منها |
| **مراجعة النشاط** | تصنيف [فترات المراجعة](./FEATURES.md#geofencing-and-work-type-location-policies) (Review segments): مدفوع (Paid) / غير مدفوع (Unpaid) / اجتماع (Meeting) للمرؤوسين المباشرين |
| **رؤية الفريق** | عرض ملفات الفريق والحضور وأرصدة الإجازات وجداول النشاط |
| **Performance (PMS) — الأداء** | مراجعة الأهداف والنتائج الرئيسية والتقييمات للمرؤوسين المباشرين (عند الاستحقاق) |
| **Recruitment — التوظيف** | المشاركة في المقابلات وتقييم المرشحين (عند التعيين) |

### ما لا يستطيع المديرون عادةً فعله

- تعديل إعدادات على مستوى المؤسسة
- الوصول إلى موظفين خارج سلسلة التبعية الإدارية (ما لم تُمنح صلاحيات أوسع)
- إنشاء قسائم الراتب أو تعديل عقود الرواتب
- ضبط السياج الجغرافي أو سياسات النشاط أو إعدادات النظام الأخرى

### الصلاحيات المعتادة

صفوف الموافقة في [لوحة المعلومات](./FEATURES.md#dashboard). عرض نشاط الفريق (Team Activity). الوصول إلى ملفات الموظفين للمرؤوسين المباشرين. صلاحيات عرض خاصة بكل وحدة.

السيناريوهات: [حالات الاستخدام — المدير](./USE_CASES.md#manager-scenarios).

## Employee — الموظف

**أين:** مساحة عمل الموارد البشرية للعميل (+ [تطبيق سطح المكتب](./FEATURES.md#geofencing-and-work-type-location-policies) اختياري).

**من:** كل شخص لديه حساب مستخدم في المؤسسة.

### المسؤوليات (الخدمة الذاتية)

| المجال | الإجراءات |
|--------|-----------|
| **[الحضور والانصراف](./MODULES.md#attendance) (Attendance)** | تسجيل الحضور والانصراف يومياً |
| **[الإجازات](./FEATURES.md#leave-management) (Leave)** | طلب الإجازات، عرض الأرصدة |
| **الملف الشخصي** | عرض وتحديث المعلومات الشخصية الخاصة |
| **الطلبات** | تقديم تصحيحات الحضور، تغييرات الوردية، طلبات نوع العمل، طلبات الاسترداد، طلبات الأصول |
| **[تسجيل التعرف على الوجه](./FEATURES.md#geofencing-and-work-type-location-policies) (Face registration)** | تسجيل قوالب الوجه للتحقق عند تسجيل الحضور |
| **النشاط (Activity)** | تشغيل تطبيق سطح المكتب، عرض جدول النشاط الخاص و[درجة الإنتاجية](./FEATURES.md#geofencing-and-work-type-location-policies) (Productivity score) |
| **قسائم الراتب (Payslips)** | عرض قسائم الراتب الخاصة (عند السماح) |
| **[Helpdesk — مكتب المساعدة](./MODULES.md#helpdesk)** | إنشاء تذاكر الدعم |
| **[Projects — المشاريع](./MODULES.md#projects)** | تسجيل ساعات سجل الوقت (Timesheet) على المهام المعيّنة (عند الاستحقاق) |
| **[Performance (PMS) — الأداء](./MODULES.md#performance-pms)** | تحديد الأهداف والنتائج الرئيسية وتتبعها (عند الاستحقاق) |

### ما لا يستطيع الموظفون فعله

- عرض قسائم راتب الموظفين الآخرين أو السجلات التأديبية أو المعلومات الخاصة في ملفاتهم
- الموافقة على الطلبات (ما لم يكونوا مديرين أيضاً)
- الوصول إلى إعدادات الإدارة أو إعدادات النظام
- عرض نشاط الفريق (ما لم يكونوا مديرين أيضاً)

### الصلاحيات المعتادة

وصول الخدمة الذاتية إلى الملف الشخصي والحضور والإجازات والوحدات المسموح بها. زر [الإجراءات السريعة](./FEATURES.md#quick-actions) (Quick action) للطلبات الشائعة.

السيناريوهات: [حالات الاستخدام — الموظف](./USE_CASES.md#employee-scenarios).

## Recruiter — مسؤول التوظيف

**أين:** مساحة عمل الموارد البشرية للعميل (وحدة [Recruitment — التوظيف](./MODULES.md#recruitment)).

**من:** أعضاء فريق الموارد البشرية أو مديرو التوظيف المتخصصون في استقطاب الكفاءات.

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **إدارة مسار التوظيف** | إنشاء حملات التوظيف، إدارة المراحل، نقل المرشحين |
| **سجلات المرشحين** | إضافة المرشحين، جدولة المقابلات، تسجيل النتائج |
| **التقييمات** | استخدام الاستبيانات ومجمع المهارات (Skill Zone) |
| **التعيين** | نقل المرشحين إلى حالة «تم التعيين» → يُطلق [Onboarding — التهيئة](./MODULES.md#onboarding) |
| **التقارير** | عرض تحليلات التوظيف في لوحة المعلومات |

### الصلاحيات المعتادة

وصول كامل إلى وحدة Recruitment. صلاحية عرض سجلات الموظفين المرتبطة بالمرشحين المعيّنين. قد يكون لديه أيضاً صلاحيات مسؤول الموارد البشرية أو المدير.

السيناريو: [حالات الاستخدام — التوظيف عبر مسار التوظيف](./USE_CASES.md#hire-through-the-pipeline).

## Payroll specialist — أخصائي الرواتب

**أين:** مساحة عمل الموارد البشرية للعميل (وحدة [Payroll — الرواتب](./MODULES.md#payroll)).

**من:** أعضاء فريق المالية أو الموارد البشرية المسؤولون عن معالجة التعويضات.

### المسؤوليات

| المجال | الإجراءات |
|--------|-----------|
| **العقود (Contracts)** | إنشاء عقود التوظيف وإدارتها |
| **البدلات والخصومات (Allowances and deductions)** | ضبط مكونات الراتب |
| **إنشاء قسائم الراتب** | تشغيل إنشاء قسائم الراتب الشهرية أو الدورية |
| **المصروفات (Reimbursements)** | معالجة طلبات استرداد المصروفات |
| **صرف الإجازات والسلف (Encashments and advances)** | إدارة صرف الإجازات والسلف على الراتب |
| **ضبط الضريبة** | إعداد قواعد الضريبة الاتحادية (Federal tax) |
| **التحقق** | التأكد من التحقق من الحضور قبل تشغيل الرواتب |

### ما لا يستطيع أخصائيو الرواتب عادةً فعله

- تعديل سجلات الحضور مباشرة (التحقق من الحضور مسار عمل المدير)
- تغيير إعدادات المؤسسة غير المرتبطة بالرواتب
- الوصول إلى وحدات Recruitment أو Performance (ما لم يُمنح ذلك)

### الصلاحيات المعتادة

وصول كامل إلى وحدة Payroll. صلاحية عرض معلومات عمل الموظفين وسجلات الحضور المتحقق منها.

السيناريو: [حالات الاستخدام — تشغيل قسائم الراتب الشهرية](./USE_CASES.md#monthly-payslip-run).

## ضبط الصلاحيات

يقوم مسؤولو الموارد البشرية ومديرو المؤسسة بضبط الصلاحيات عبر:

| الآلية | الغرض |
|--------|-------|
| **صلاحيات الموظف (Employee permission settings)** | تعيين صلاحيات فردية لكل موظف |
| **مجموعات المستخدمين (User groups)** | قوالب أدوار (مثل «فريق الموارد البشرية»، «مديرو الأقسام») تُطبَّق على عدة مستخدمين |
| **صلاحيات على مستوى الوحدة (Module-level permissions)** | صلاحيات عرض وإنشاء وتعديل وحذف لكل وحدة |
| **علاقة المدير المباشر (Reporting manager relationship)** | تحدد صفوف موافقة المدير ورؤية الفريق |

الصلاحيات دقيقة — يمكن للموظف أن يحمل عدة أدوار (مثل: مدير + أخصائي رواتب).

## علاقات التبعية الإدارية

حقل **المدير المباشر** (Reporting manager) في معلومات عمل الموظف يحدد:

- أي صفوف الموافقة تظهر في [لوحة المعلومات](./FEATURES.md#dashboard) للمدير
- رؤية الفريق في وحدات Activity والحضور والإجازات
- تعيينات مراجعات الأداء

هذا منفصل عن أدوار مدير المشروع (Project manager) في [وحدة Projects — المشاريع](./MODULES.md#projects)، التي تتحكم في الوصول الخاص بالمشروع فقط.

---

## الوصول أثناء إيقاف الحساب

عند إيقاف مساحة عمل العميل أو إلغائها:

- تفقد جميع الأدوار الوصول فوراً عند التفاعل التالي
- يحتفظ [مشغّلو المنصة](#platform-operator) بوصول لوحة التحكم لإدارة الحساب
- تُحفظ البيانات لجميع الأدوار حتى حذف مساحة العمل

السياسة: [الوصول إلى الحساب](./POLICIES.md#account-access-and-entitlements).
